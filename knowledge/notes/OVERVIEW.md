## 2. この器から今見えている pjdhiro の主軸（仮）

- **量より向き**：大きさ（振幅）だけでなく **向き（位相）** で世界を見る。震災で「大きさだけでなく位相」に気づいた、という原体験が根にある
- **足し算でなく掛け算**：物事を線形な積み上げでなく、**回転・向きの合成**として捉える
- **統合は「減る」体験**：別々に覚えたものが共通の骨格に畳まれると、知識は増えるのでなく **減る**（＝見通しが良くなる）。これを快として語る
- **分解できることへの信頼**：回転は行列に分解できる。多次元の回転も。「分解できる」という気づき自体を価値として扱う

## 3. ハーネス／他 repo との結びつき（洞察・仮）

中心仮説：**pjdhiro の「回転・位相・分解」という世界の見方は、repo 群とハーネスの設計判断の中に、すでに外化されている。** ノートは思考の記録であると同時に、なぜ今の構造になっているかの説明変数になっている。

### 3-1. 回転メタファ ↔ repo 群の配置（本人が投稿で明言している対応）

| repo | 投稿での位置づけ | 回転での見え方 |
|---|---|---|
| `creation-space`（創造・客観・物質・科学） | ハードっぽいほう | 主軸 |
| `awareness-space`（意識・主観・精神・感情） | ソフトっぽいほう | cs を **90度回した**軸 |
| `kesson-space`（欠損駆動思考） | 主軸に対し回した軸を走る信号を、信号のまま **問いとして抱持** | 回した軸の上の信号そのもの |
| `project-design`（Love-Driven Dev） | 日々の営みをざっくりまとめる | それらの**統合・合成** |

→ **repo 群の分割そのものが、本人の「回転で世界を切る」視点の外化**になっている可能性。
cs と as が「90度の対」であること、ks が「回した軸の信号の抱持」であることは、
CLAUDE.md が pd を「cs（創造のモデル）・ks（欠損駆動思考）を**部品として引用**して積み上げる拠点」と
定義する構図と重なる。**分けて、回して、また積む。**

### 3-2.「減る知識」↔ ハーネスの集約思想

投稿の核「別々に覚えたものが同じ骨格だった。知識が増えたんじゃない、減ったんだ」は、
このハーネスの設計判断と **同型**に見える：

- **共通 hooks の正本集約**（CLAUDE.md §共通 hooks）：8 本の共通 hook を **pd に正本**として置き、
  cs・ks・as は相対 symlink で参照。各 repo が別々に持っていたものを一つの骨格に畳んだ＝**減らした**
- **design-system の三層分解**（CLAUDE.md §design-system）：
  - メタ共通 `--ds-*`（3 repo 値一致の基底）
  - pd 固有 `--pd-*`
  - repo 個性 `--kesson-* / --cs-* / --as-*`（intentional difference）

  これは「**共通の基底 ＋ 各 repo の残差**」への分解で、行列分解（共通成分を括り出し、個性だけ残す）と発想が同じ。
  「i を開いて行列にする」「共分散行列／バリマックス回転で値を回す」という投稿の語りと地続き。

→ つまり **本人の epistemics（同じ骨格を見つけて減らす快）が、そのまま repo 横断の集約アーキテクチャの動機**になっている。ハーネスは技術的都合だけで集約されたのではなく、この世界観の現れとして読める。

### 3-3. 「向きと位相」↔ 欠損駆動思考の操作

投稿の「主軸に対し回した軸を走る信号を、信号のまま問いとして抱持する」は、
**位相の違う信号を、振幅（大きさ）に潰さずに保持する**操作と読める。
これは欠損駆動思考の中核操作（不快・混乱を保持論点として残す＝CLAUDE.md「保持論点を急いで解くな」）と
**同じ運動の別表現**かもしれない。回転の直観と ks 理論の接続点（保持）。
