# CN-021: 「誰のものか言えるか」と「そこへ書き込んでよいか」は別の条件 — 1つの旗にまとめない

**作成日**: 2026-09-06
**ステータス**: [S] 探索的（実務からの帰納・1事例）
**関連**: CN-013（検査は不変条件で書く）, CN-015（消えない参照層を分ける）,
CN-019（入口だけ守り、本体は自分で証明を検証して振り分ける）, gonin#76・#77
**出典**: gonin のセッションログの入口 `scripts/session-log.sh` を myhome から移植した作業（2026-09-06）。
一次記録は gonin#77 と `gonin/.cache/session/log-20260906-411.md`

---

## なぜこのノートがあるか

キャッシュ・冪等キー・セッションID・ロックのように、**「前と同じものか」を見て振る舞いを変える機械**を書くと、
たいてい「その判定を信用してよいか」を1つの真偽値にまとめたくなる。

```
if 信用できる: キャッシュを使う（読む・書く）
else:          使わない
```

この形は、**信用できない理由が1つしかないうち**は正しく動く。
理由が2つ以上になった時点で、**片方だけに効くはずの用心が、もう片方まで巻き込む**。

読みと書きでは、危険の向きが違うからである。

| | 間違えたとき何が起きるか |
|---|---|
| **読み** | 他人のものを自分のものとして**引き継ぐ** |
| **書き** | 自分のものを他人の場所へ**焼き付ける**（次に来た人が黙って引き継ぐ） |

---

## 事例（gonin#76 → #77・2026-09-06）

セッションIDを2回採らないために、transcript（対話ログ）の uuid をキーにしたマーカーを置いた。

```bash
if [ "$TRANSCRIPT" != "（未特定）" ] && [ -z "$TRANSCRIPT_NOTE" ]; then MARKER=... fi
```

`TRANSCRIPT_NOTE` には、**性質の違う2つの警告**が入っていた。

| 注記 | 何を言っているか | 本当に封じるべきは |
|---|---|---|
| 並行（3分以内に複数の .jsonl） | **どれが自分のものか言えない** | 読みも書きも |
| 古い（10分以上更新が無い） | **誰のものかは分かる。動きが止まっているだけ** | 書きだけ |

uuid はセッションを一意に指す。**古いことは「誰のものか」を曇らせない。**
それなのに同じ旗にまとめていたので、少し間の空いたセッションが採番をやり直し、
**同じセッションに 20260906-411 と 20260906-420 の2つの ID が出た**（空のログが2組できた）。

### 直し方

旗を2つに割った。**判定の材料は同じで、使い道ごとに条件が違う**。

```bash
if [ "$TRANSCRIPT" != "（未特定）" ] && [ "$AMBIGUOUS" = 0 ]; then
  MARKER=...                                   # 読む＝一意に指せていれば足りる
  [ -z "$TRANSCRIPT_NOTE" ] && MARKER_WRITABLE=1  # 書く＝いま生きている確証も要る
fi
```

⚠️ **緩めたのではない。** 書き込み側の条件は1文字も動かしていない。
動いたのは「読みにまで書き込みの用心を掛けていた」ぶんだけである。

---

## 見分け方

**1つの真偽値が、2つ以上の理由で false になっていないか数える。**

数え方＝その旗が false になる原因を列挙し、原因ごとに「これは読みを止めるのか、書きを止めるのか、両方か」を書き出す。
**列が揃わなければ、旗は2つ以上に割れている。**

⚠️ 逆に、原因が違っても**止める先が全部同じ**なら割ってはいけない（旗が増えるだけで何も守らない）。

徴候として出やすいもの:

- 変数名が `*_NOTE`・`*_WARNING`・`is_safe`・`ok` のように、**何を止めるかを名指ししていない**
- 「念のため」で足した条件が、あとから別の目的に使い回されている
- 用心を強くしたのに、**現場で毎回それを迂回する手順**が生えている（＝強すぎる側に当たっている）

---

## 得られるもの

- **用心を弱めずに、誤爆だけを消せる**。安全側の条件はそのまま残る
- 条件に名前が付く（`AMBIGUOUS` / `MARKER_WRITABLE`）＝**読む人がどちらの心配をしているか分かる**
- 検査が書けるようになる。旗が1つのときは「安全か」しか問えないが、割れば
  「一意に指せているのに引き継がなかった」という**不変条件**を試験にできる（CN-013）

## 代償

- 条件が増えるぶん、**組み合わせの試験が要る**（今回は 古い×有／古い×無／並行／新しい の4通りを実機で回した）
- 割り方を間違えると、**弱いほうの条件が危険な側に付く**＝割る前より悪い。
  だから割るときは「間違えたとき何が起きるか」を先に書き、**強い条件は動かさない**と決めてから触る

## いつ使うか

- キャッシュ・冪等キー・再開（resume）・ロック・重複排除など、**同一性の判定で分岐する**機械を書くとき
- 「安全のため使わない」で倒した設計が、**現場で毎回作り直しを強いている**とき
- 権限の設計＝「読めるか」と「書けるか」を1つのフラグで持っていないか

## 隣の概念との関係

- **CN-019（入口だけ守り、本体は自分で証明を検証して振り分ける）** ＝同じ骨格の権限版。
  「守る場所」と「振り分ける場所」を分けたのが CN-019、「読む条件」と「書く条件」を分けたのが本ノート
- **CN-015（消えない参照層を分ける）** ＝1つの器に寿命の違うものを同居させると片方に引きずられる、という同じ病の**データ側**
- **CN-013（検査は不変条件で書く）** ＝割ったあとに何を試験すべきかを与える
