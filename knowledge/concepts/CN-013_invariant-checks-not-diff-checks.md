# CN-013: 検査は不変条件で書く — 差分ベースの検査は「壊れた期間だけ無音」になる

**作成日**: 2026-08-02
**ステータス**: [S] 探索的（実務からの帰納・1事例＋既存事例の再解釈）
**関連**: CN-012（並行エージェント環境のブランチ照合）, myhome `garden/lessons.md` 26,
myhome `scripts/bed-area-check.py`（`garden-check.sh [13]`）, myhome `scripts/bed-sync-check.py`（同 [11]）
**出典**: myhome の畝面積ドリフト（2026-08-02）。一次記録は myhome `garden/lessons.md` 索引26 と

## なぜこのノートがあるか

「文章のルールで守れなかった所は機械化する」という方針を採ると、**次に必ず問われるのは
「その機械はいつ発火するか」**である。ここを差分（git diff）に置くと、**検査は静かに死ぬ**。

実測した事故: myhome の畑で **畝の総数（21畝＝28.2㎡）だけが誰にも検算されず、
古い値（12畝＝16.8㎡）が5つのファイルに3日以上残った**。しかも**資材の必要量はこの総面積から
逆算していた**ので、表記のズレではなく**手配量の誤り**になっていた。

この repo には既に**差分ベースの検査が2本**（変更した畝名を他ビューで列挙する [11]、
ログの追記から todo の消し忘れを列挙する [12]）あり、どちらも設計としては正しく動いていた。
それでも捕まらなかった。**理由が2つとも構造的**だったのが、このノートの主題である。

---

## 1. 差分ベースの検査が取りこぼす2つの型

### 型A: 差分に「名前」が現れないもの（＝集計値・派生値）

[11] は **「変更した畝名を含む行」**を列挙する。しかし総数の行——

> 現状12畝＝約16.8㎡・年2作

——には**畝名が1つも無い**。したがって**どれだけ畝を触っても、この行は永久に候補に挙がらない**。

一般化: **差分ベースの検査は「変更したものの名前」を鍵に探す**。
**集計値・派生値・比率・合計は、その名前を持たない**。よって原理的に見えない。

### 型B: 窓が閉じる

[11] は git の差分（作業ツリー／merge-base／直近48h）を起点にする。
ノイズを避けるため「48h の窓に N 畝以上の変更が入ったら一括整備とみなして列挙を畳む」
という妥当な安全弁を持っていた。

ところが**まさにドリフトしていた期間**に一括整備（全27畝への列追加）が入り、
**閾値を超えて列挙を畳んで無音**になった。

一般化: **差分ベースの検査は「変更が多い時期」に最も弱い**。
しかし**変更が多い時期こそ壊れやすい**。**検査の感度と事故率が逆相関する**。

---

## 2. 不変条件ベースへの置き換え

対策として置いたのは、**差分を一切見ない検査**である。

| | 差分ベース | 不変条件ベース |
|---|---|---|
| 起点 | 「何が変わったか」 | 「いま何が真であるべきか」 |
| 発火 | 変更があったときだけ | **毎回** |
| 窓 | 閉じる（マージ・一括整備・時間経過） | **閉じない** |
| 見えるもの | 変更した対象の名前 | **全体の整合** |
| コスト | 安い（差分の分だけ） | 全走査（小規模なら無視できる） |

実装（myhome `bed-area-check.py`）:

1. **正本を1つに決める**（畝の現況＝`bed-map.md`）
2. そこから**総数を計算する**（畝数・作土面積・占有面積）
3. 書き写した先を**生成ブロックにして厳密照合**する（ズレたら fail、`--update` で書き直す）
4. 生成ブロックにできない散文の総数は**列挙して人に返す**（判定は人／モデル）

---

## 3. 一般則 — 「合計は書き写さず生成する」

事故の根はドリフトそのものではなく、**同じ事実の正本が2つあったこと**である
（物理区画の文書が、現況の畝数まで持っていた）。

> **派生値・集計値は書き写した瞬間に第2の正本になる。**
> **第2の正本は必ず古くなる。**

したがって:

- **合計・比率・必要量は生成物にする**（この repo で先行例がある: 支出サマリを明細から作り直す `--update` 方式）
- **生成物は検算する**（生成できるものは照合できる。照合できるものは腐らない）
- **わざと古い値を残す行には明示の逃げ道を置く**（`<!-- area-ok -->`。抑止マークが無いと、
  正当な経緯の記述まで直しにいって履歴を壊す）

---

## 4. 適用の目安

すべてを不変条件にする必要は無い。**差分ベースが正しいのは「人の判断が要る列挙」**で、
**不変条件が要るのは「機械が真偽を決められる関係」**である。

| 検査したいもの | 向く型 |
|---|---|
| 変更した X が他の文書と食い違わないか（判定は人） | 差分 |
| **合計・比率・必要量が元データと一致するか** | **不変条件** |
| **生成物が元データから再生成できるか** | **不変条件** |
| 書き忘れ・消し忘れの候補列挙 | 差分 |

⚠️ **差分ベースの検査を持っていること自体が油断を生む**。
「[11] があるから畝まわりは守られている」と思っていた期間が、そのままドリフトの期間だった。
**既存の検査が何を見ていないかを、検査ごとに1行で書いておく**のが安い予防になる。
