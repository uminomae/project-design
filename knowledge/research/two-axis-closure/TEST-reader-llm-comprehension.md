# READER 公開ページ — LLM 読解テスト

**目的**: 文脈ゼロの LLM が公開ページ *だけ* を読んで、主旨・概要・アウトライン・流れを取り違えず再構成でき、難解概念を平易に言い直せるかを検証する。テストのたびに **コンテンツ（READER）とテスト（本ファイル）の両方**を修正して推敲を重ねる（pd#127・ルール16）。

## 手順（1 ラウンド）

1. `node scripts/reader-llm-comprehension-test.mjs` を実行 → 公開 HTML から「文脈ゼロで読むプレーンテキスト」を抽出（`<details>` も展開し、隠れを排除）し、下の質問群を束ねたプロンプトを生成する（出力は `.cache/active/`・ローカル）。
2. **文脈ゼロの LLM 読者**（サブエージェント等。事前知識・本リポジトリの文脈を一切与えない）に、生成テキストだけを読ませ、規定の質問群に回答させる。⚠️ **サブエージェントの CWD はワークツリー側になりうる**ため、出力ファイルは**絶対パス**（`<repo>/.cache/active/reader-context-zero.txt` 等）で渡すこと（相対パスだとワークツリーに無く読めない）。
3. Main が回答を下のルーブリックで採点し、**誤読・曖昧点・二義的な読み**を収集する。
4. **コンテンツを修正**（READER 本文）し、**同時にテストも改良**（質問の追加・言い換え、ルーブリックの精緻化）。
5. LP 再ビルド（`python3 scripts/build-reader-lp.py`）→ static-checks・UTF-8・アンカー確認。
6. 回帰確認（同じ質問群を再度）→ 合格基準を満たすまで反復。

## 採点ルーブリック

各観点を 3 段階で採点する。**目標は全観点 PASS**。

| 記号 | 意味 |
|---|---|
| ✅ PASS | 取り違え・誤読なし。テキストだけから一意に導けている |
| ⚠️ WEAK | 大筋は合うが、曖昧・二義的・言い淀みがある（テキスト側の可読性課題の疑い） |
| ❌ FAIL | 取り違え・誤読・断絶の指摘漏れ・捏造（テキスト側の欠陥が濃厚） |

- **⚠️/❌ は原則テキスト（コンテンツ）側の課題として扱う**——LLM 読者を賢くするのではなく、ページを直す（ルール16 の趣旨）。ただし質問が曖昧で誤答を誘発した場合は**テスト側**を直す。
- 収集した誤読・曖昧点は「検出項目」として下のラウンド記録に残し、修正（コンテンツ/テスト）と対応づける。
