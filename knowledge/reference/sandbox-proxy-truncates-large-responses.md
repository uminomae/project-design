# サンドボックスのプロキシは大きな応答を約 192KB で打ち切る

**確認日**: 2026-09-07（investing・Deribit の約定履歴取得。初出は 2026-08-31 の COT/Deribit 取得）

## 事実

Claude Code のサンドボックス内から HTTP を叩くと、**応答が大きいとき本文の途中で接続が切れる**。
Python からは `http.client.IncompleteRead` として出る。

```
http.client.IncompleteRead: IncompleteRead(193140 bytes read)
http.client.IncompleteRead: IncompleteRead(111516 bytes read, 12638 more expected)
```

- 打ち切りは **190KB 前後**で起きる（実測 193,140 バイト・111,516+12,638＝124,154 バイトの回もある）。
  **固定の閾値というより、egress プロキシがチャンク転送を途中で落とす**形
- ⚠️ **TLS でも認証でもレート制限でもない**。同じ URL を**サンドボックス外**で叩くと最後まで返る
- ⚠️ **エラーがサーバ側の顔で出る**＝ライブラリは「サーバが約束した長さを送ってこない」と言うので、
  API を疑って何度も叩き直すことになる。**疑うべきは経路**

## いつ踏むか

**1リクエストの応答が大きい API**。ページングの1ページを大きく取る設計ほど早く踏む。

- 実例1: Deribit `get_last_trades_by_instrument_and_time` の `count=1000`（約定 1000 件・数百 KB）
- 実例2: CFTC の COT 一括ダウンロード、Deribit の全限月 OI、Yahoo の長期日足（2026-08-31 実測）

## 逃がし方

1. **1リクエストの応答を小さくする**（`count` や期間を刻む）＝根本的だが呼び出し回数は増える
2. **サンドボックス外で走らせる**＝`dangerouslyDisableSandbox: true`。
   ⚠️ **承認プロンプトが出るので、無人タスクでは使ってはいけない**（そこで永久に止まる）
3. **launchd など、そもそもサンドボックス外で回る経路に任せる**＝定期取得はこちら。
   対話セッションから手で叩くときだけ 2 が要る、という切り分けになる

⚠️ **「毎日動いているのに、手で叩くと落ちる」ときはこれを疑う**。スクリプトのバグではなく、
**launchd（外）と対話セッション（中）で経路が違う**だけのことがある。
